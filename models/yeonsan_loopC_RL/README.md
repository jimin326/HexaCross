# yeonsan_loopC_RL: 루프 경로 C (모방학습 신경망 → 강화학습)

연산교차로 북쪽에서 출발해 월드컵대로 남쪽 → 연수로 좌회전 → 쌍미천로 좌회전(북쪽) → 고분로 좌회전 → 연산교차로 동쪽으로 다시 들어와 서쪽으로 나가는 루프 경로 C를 학습한 **단일 신경망**이다 (앙상블 아님). J8의 구성원 신경망 하나(m6)에서 시작해 PPO 강화학습으로 140만 스텝 학습했다.

## 결과 (교통량 1.0, 결정적 정책, libsumo, 480회)

| 평가 | 완주 | 충돌 | 신호위반 | 차로 오류 |
|---|---|---|---|---|
| 시드 921~954 (240회) | 97.92% | 0% | 2.08% (5) | 0% |
| 시드 961~994 (240회) | 97.08% | 0.42% (1) | 2.50% (6) | 0% |
| **합계 480회** | **97.50%** | **0.21% (1)** | 2.29% (11) | 0% |
| 목표 | 95% 이상 | 2% 이하 | | |

같은 조건(60회, 시드 921~924)에서 시작 모델은 다음과 같았다.
- J8(앙상블 8개, 모방학습): 완주 93.3%, 신호위반 6.7%.
- m6(J8의 구성원 하나, 시작점 `il_init_m6.pt`): 완주 93.3%, 신호위반 6.7%.
- 이 모델(m6 + PPO 140만 스텝): 60회 기준 완주 95.0%, 충돌 1.67%. 240회 기준으로는 위 표와 같다.

## 경로와 지도

| 항목 | 내용 |
|---|---|
| 지도 | `env/maps/yeonsan_area.net.xml` (대로 중심 넓은 지도, 루프 B와 같음) |
| 경로 | 연산 N 진입 → 월드컵대로 남쪽(`-26005519`) → 연수로 동쪽(`773756903`) → 쌍미천로 북쪽(`37401760#1`) → 고분로 서쪽(`794688376#1`) → 연산 E 진입 → W 진출 |
| 길이 | 19개 도로, 4,796 m (루프 부분은 약 3.7 km), 신호 7곳 |
| 설정 | `tools/rl/routes7.py`의 `ROUTE_SET=loopC` (경로 1개 = `ego_0`, `N_ROUTES=1`) |
| 에피소드 길이 | `MAX_STEPS=6000` |

## 만든 과정

1. **기준선**: J8은 C를 처음 달려도 차로 문제가 없었다(큰길 좌회전 3번). 실패는 거의 신호위반이었다.
2. **DAgger 1차** (`dgC1`): J8이 운전(BETA 0), 4 × 20회. 완주 75, 차로 오류 5.
3. **황색 신호 정답 보정** (`tools/rl/relabel_yellow.py`): 루프 B와 같은 규칙. C 데이터는 황색 표본을 4배로 복사했다. J8_RL의 7경로 모방학습 데이터(`models/yeonsan_7routes_J8_RL/bc_ft.npz`)도 같은 규칙으로 보정했다.
4. **시작 신경망 고르기**: J8 구성원 8개를 C에서 하나씩 평가해 m2·m4·m6(10/10 완주) 중 m2와 m6로 PPO를 돌렸다.
5. **PPO** (`tools/rl/residual_train.py`, `INIT_MODEL`, 설정은 루프 B의 sr1과 같음)
   - 학습률 3e-5, 모방학습 손실 가중치 1 → 0.1 (200만 스텝 동안 선형 감소)
   - 모방학습 손실 데이터: 보정한 7경로 데이터 + 보정한 C DAgger 데이터(2배)
   - 신호위반 30, 충돌 50, 차로 오류 10, TTC 0.3, 위험 장면 재시작 30% (`DANGER_RED=1`)
   - 20만 스텝마다 스냅샷을 60회로 평가하고, 목표선에 든 스냅샷을 240회로 확인했다. **1,400k 스냅샷을 채택했다.**

## 평가

```bash
ROUTE_SET=loopC MAX_STEPS=6000 LANE_PLAN_RANGE=300 OBS_VISIBILITY=100 LANE_ARROWS=1 INTERNAL_OBS=1 OMP_NUM_THREADS=1 SEED=921 \
python tools/rl/eval_routes.py models/yeonsan_loopC_RL/model.pt <SUMO 작업 폴더> 15 out.json
```

- SUMO 작업 폴더는 `ROUTE_SET=loopC`를 켠 상태에서 `road_builder.build`로 만든다. `residual_train.py`는 첫 실행 때 자동으로 만든다.
- `eval_routes.py`는 이제 libsumo로 돈다 (TraCI보다 수십 배 빠름, `EVAL_TRACI=1`이면 예전 방식). TraCI와 libsumo는 같은 시드라도 주행이 달라 숫자를 섞어 비교하지 않는다.
- `OMP_NUM_THREADS=1`을 꼭 준다. 여러 평가를 동시에 돌릴 때 계산 스레드가 서로 CPU를 다퉈 평가가 수십 배 느려졌다.

## 주의

- 스냅샷마다 성능 편차가 크다 (같은 학습 안에서 60회 기준 61.7% ~ 96.7%).
- 60회 평가(시드 921~924)가 240회보다 낙관적으로 나왔다. 802k·1200k는 60회 95%였지만 240회 90%대였다. 후보는 반드시 240회 이상으로 확인한다.
- 같은 시드로 다시 평가해도 결과가 똑같지 않다 (SUMO 실행 간 미세 차이). 채택 모델을 시드 961로 다시 돌리니 15회 중 완주가 14 → 15로 달라졌다. 판정은 480회처럼 큰 표본으로 한다.
- 남은 실패는 대부분 신호위반이다. 실패 장면 기록에서는 고분로 → 연산 동쪽 진입 마지막 정지선(`x6_E_in1`) 20~25 m 앞에서 황색이 켜졌을 때 속도를 유지하다 적색에 넘는 경우가 많았다.
- 해 봤지만 손해였던 것:
  - 모방학습 손실 가중치를 1로 고정(1,003k에서 이어서): 차로 오류 26.7%로 늘었다.
  - 신호위반 페널티 100 (보정 데이터로 새로 학습한 시작점에서): 200k에서 완주 8.3%로 무너졌다.
