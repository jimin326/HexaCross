**충돌 원인 분석 (E8, G8에서 충돌을 하나씩 재현)**
1. **교차로 안 충돌 (약 3분의 2):** 같은 차로에서 좌회전 연결 차로로 들어가다 멈춘 차의 뒷부분이 내 직진 경로를 막았습니다. SUMO `getLeader`가 내 경로의 연결 차로만 따라가서 이 차를 못 봤습니다. → **앞 차체 감지**로 고쳤습니다(`env/sumo_env.py`의 `_corridor_leader`). 센서가 앞을 보는 것과 같은 물리적 관측이라 공지 범위 안이라고 판단했습니다.
2. **차로 변경 중 옆 충돌:** 대부분 E→W 월드컵대로 진출부에서 났습니다. 관측에는 옆 차가 "간격 0, 나보다 빠름"으로 제대로 있었는데도 학생이 차로를 바꿨습니다. 원인은 예전 보강이 "느린 앞차"와 "가까운 뒤차"만 만들었기 때문입니다. → **넓은 보강**으로 고쳤습니다(나란히 겹친 차, 가까운 앞차를 속도와 상관없이 넣음).

1. 충돌 감점 10은 에피소드당 진행 보상(약 22)보다 쌌습니다. 그래서 정책이 위험을 감수하고 빨리 가는 쪽을 배웠습니다(res5). 50으로 올리자 이 문제는 줄었습니다(res6).
2. 충돌은 에피소드의 2~3%에서만 났습니다. 200만 스텝을 학습해도 충돌 경험이 50번 남짓이라 보상 신호가 부족했습니다. 위험 상황 재시작으로 경험을 늘렸지만, 학습한 위험 상태에만 맞춰졌습니다.
3. 기본 운전자가 이미 아주 강했습니다. 보정만 학습하는 구조로는 차로 변경 판단을 고칠 수 없었습니다.
4. 같은 기간에 관측을 고치고 데이터를 보강하는 쪽(앞 차체 감지, 넓은 보강)이 훨씬 효과가 컸습니다.

## 전체에서 배운 점 (보고서 요약용)

1. **보상만으로 하는 강화학습은 이 문제에서 한계가 뚜렷했습니다.** 완주가 60~70%에서 멈췄고, 시드에 따라 결과가 크게 갈렸습니다. 특히 "몇 백 m 앞에서 맞는 차로로 미리 옮기기"를 보상만으로 배우기 어려웠습니다.
2. **모방학습이 기본기를 만들었습니다.** 다만 전문가를 그대로 따라 하면 실패했고(완주 3%), 학생이 따라 하기 쉽게 여유를 둔 "교사 보정"이 결정적이었습니다(82%).
3. **DAgger와 앙상블이 안정성을 만들었습니다.** 학생이 실제로 들어간 상황에서 정답을 받고, 서로 다른 모델 8개를 평균했습니다. 같은 데이터로 학습한 모델 하나하나는 결과가 크게 흔들렸습니다.
4. **충돌을 줄인 것은 대부분 원인 분석이었습니다.** 충돌을 하나씩 재현해 원인을 찾고 관측(앞 차체 감지)이나 데이터(넓은 보강)를 고쳤습니다. 보상을 손보는 것보다 효과가 훨씬 컸습니다.
5. **강화학습은 모방학습 위에서 "다듬기"로 쓸 수 있었습니다.** 앙상블 전체를 모방학습 손실과 함께 낮은 학습률로 미세조정했습니다.
   - 학습 교통(0.85)에서는 충돌이 J8보다 줄었습니다.
   - 학습 비중이 작은 교통(0.7)에서는 신호 위반이 늘었습니다.
   - 오래 학습하면 나빠져서 저장본을 골라야 했습니다.
6. **감점 크기의 균형이 중요했습니다.**
   - 충돌 감점이 진행 보상보다 싸면 속도를 택했습니다.
   - 감점이 너무 크면 기어가기·서 있기에 빠졌습니다.
