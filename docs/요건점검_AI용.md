## 1. 조교가 정한 규칙 (요지)

### 주행할 때 (평가·데이터 수집 때 AV가 달리는 동안)

| # | 규칙 | 근거 |
|---|---|---|
| R1 | 최종 AV는 **학습한 신경망 하나**가 행동을 낸다. 주행 중에 규칙·다른 모델이 개입하면 안 된다 | FAQ "규칙 기반·MLP로 시나리오 선택·도움 → 안 됨", 12조 |
| R2 | 위험 신호가 오면 출력에 보정값을 켜는 구조(예: `tanh(z(s) + g(s)·r(s))`, g = 위험 신호 0/1)는 **안 된다**. 보상으로 학습할 것 | 14조 댓글 |
| R3 | **정책 출력(행동)을 환경이 강제로 바꾸면 안 된다.** 예: 가속 명령이 제한속도를 넘으면 제한속도에서 자르기 → **수정 필요** | 14조 4번 |
| R4 | 차선변경 안전 검사(목표 차로 앞뒤 간격 부족 시 실행 안 함, 출발 60 m 안 변경 금지)는 **써도 된다** (수업 원본 `lane_change_safety` 포함) | 14조 1번, 4조 2번 |
| R5 | 가감속을 막는 장치는 없어야 한다 (R3과 같은 이유) | 14조 질문 전제 |
| R6 | SUMO 자동 안전제동·자동 차선변경은 꺼야 한다 (AV가 직접 운전) | 14조 질문 전제, FAQ |

### 관측 (AV 신경망 입력)

| # | 규칙 | 근거 |
|---|---|---|
| O1 | **차로 단위 경로 안내는 빼야 한다.** 예: 차로마다 "경로를 따라가려면 차선을 몇 번 바꿔야 하는지", "어느 차로로 가야 하는지" | 14조 2번, FAQ "세밀한 주행 정보 금지" |
| O2 | **큰 틀의 지도 같은 경로 정보는 괜찮다.** 예: "내 차로가 앞 50 m 안에서 끝나는지", "다음 갈림길(출구)까지 거리와 방향(왼/오른쪽)" | 14조 2번 |
| O3 | 다른 차의 의도·진행 방향처럼 사람이 볼 수 없는 정보로 "도와주는" 관측은 피한다 (예: 교차로 상충 차량 예측) | FAQ "도움 요소 금지" (팀 해석) |

### 학습할 때

| # | 규칙 | 근거 |
|---|---|---|
| L1 | BC(모방학습)로 사전 학습한 뒤 PPO로 사후 학습해도 된다. 단계별 학습 범위 제한 없음 | 1조 1번, 12조 |
| L2 | PPO 중에 전문가 데이터로 **BC 보조 손실**을 함께 써도 된다 | 4조 1번 |
| L3 | BC·DAgger 전문가로 **직접 짠 규칙 기반 운전자(IDM 등)**를 써도 된다 | 12조 1·2번 |
| L4 | DAgger 전문가가 **학생 관측에 없는 시뮬레이터 정보**(교차로 양보 판단 등)를 써도 된다. 평가 주행은 신경망 단독일 것 | 4조 3번 |
| L5 | **보상 계산**에 시뮬레이터 내부 정보를 써도 된다 | 4조 4번 |
| L6 | "실패하는 구간만 골라 PPO로 학습"은 조교가 되물었다(사람이 구간을 고르는지). 사람이 구간을 정해 그 구간만 업데이트하는 방식은 확인 전까지 피한다. 자동 위험 장면 재시작(충돌 직전 상태 저장 후 일부 에피소드를 거기서 시작)은 전체 경험으로 업데이트하므로 다르다 — 발표에서 그렇게 설명할 것 | 1조 1번 |
| L7 | 두 경로 중 하나를 출발 때 규칙으로 정해 주는 것(차량이 학습한 게 아닌 시나리오 배정)은 괜찮다 | 14조 3번 |

## 2. 점검 절차 (AI가 할 일)

저장소 루트에서 아래를 차례로 확인한다. **추측하지 말고 코드를 열어 확인하고, 파일:줄 번호를 적는다.**

1. **행동이 환경에서 바뀌는 곳 (R3, R5)**
   - `env/sumo_env.py`의 `step()`에서 가감속 명령을 SUMO에 넣는 부분(`traci.vehicle.setSpeed`, `slowDown` 등)을 찾는다.
   - 속도를 `np.clip(..., 0, vmax)`처럼 **제한속도로 자르는지** 본다. 제한속도(`ROAD["speed_limit"]`, 차로 `getMaxSpeed`)로 자르면 R3 위반.
     차량 성능 최고속도(`EGO["max_speed"]`)로 자르는 것은 물리적 한계이므로 괜찮다. 단 그 값이 제한속도와 같으면(예: 13.89 = 50 km/h) 사실상 같은 위반이다.
   - AV 차종(`ego_type` vType)의 `maxSpeed`가 제한속도와 같은지 본다 (`env/road_builder.py`, `env/osm_builder.py`).
   - 가속도 크기 한도(`EGO["accel"]`, `["decel"]`)로 행동을 스케일하는 것은 물리적 한계라 괜찮다.
   - 그 밖에 행동을 덮어쓰는 코드(신호 앞 자동 정지, 앞차 가까우면 자동 감속, 행동 마스킹 등)가 있는지 `step()` 전체를 읽는다.
2. **주행 중 개입 (R1, R2)**
   - 평가 코드(`test.py`, `tools/rl/eval_parallel.py`, `tools/rl/eval_routes.py`)와 수집 코드(`collect_pomdp_data.py`)에서 정책 출력과 환경 사이에 규칙·다른 모델·잔차 보정이 끼는지 본다.
   - 모델 파일이 앙상블·잔차 형식(`algorithms/ensemble.py`, `algorithms/residual.py`)인지 확인한다. 잔차 정책이 "위험할 때만 켜지는" 구조면 R2 위반 소지. 앙상블(여러 신경망 평균)이 R1의 "신경망 하나"에 맞는지는 **조교 확인이 필요한 회색 지대**로 보고한다.
3. **SUMO 자동 운전 (R6)**
   - AV에 `setSpeedMode(…, 0)`, `setLaneChangeMode(…, 0)`이 걸리는지 본다 (`env/sumo_env.py`). 위험 장면 재시작(`loadState`) 뒤에도 다시 0으로 설정하는지 확인한다.
4. **차선변경 안전 검사 (R4)**
   - `env/mdp_config.py`의 `ACTION["lane_change_safety"]` 설정을 적는다. 켜져 있어도 허용이므로 "허용(켜짐/꺼짐)"으로 보고한다.
5. **관측 (O1~O3)**
   - `env/mdp_config.py`의 `OBSERVATION`과 `env/sumo_env.py`의 `_get_obs`를 읽어 관측 각 칸이 무엇인지 표로 만든다 (`DATA_FORMAT.md` 4절 표와 대조).
   - `lane_route_info`가 True면 O1 위반 (차로 단위 경로 안내).
   - `junction_foes`가 켜져 있으면 O3 위반 소지.
   - 다음 교차로 회전 방향·거리(`route_turn`), 목표까지 남은 거리는 O2 허용 범위.
   - 노면 화살표(`lane_arrows`: 각 차로가 정지선에서 갈 수 있는 방향, 경로와 무관)는 조교 답이 없다 → **확인 필요**로 보고.
   - 앞 차체 감지(`corridor_leader`)는 센서가 앞을 보는 것과 같은 관측이다 → 허용으로 보되 근거를 적는다.
6. **학습 방법 (L1~L7)**
   - 학습 스크립트(`train.py`, `tools/rl/residual_train.py`, `tools/rl/dagger_collect.py`, `tools/rl/bc_train.py`)와 실행 설정(`results/*/run_patch.json`, `models/*/README.md`, `*_config.json`)을 읽는다.
   - 최종 모델이 **RL(PPO)로 학습한 단계를 거쳤는지** 확인한다 (수업 Step 4: "강화학습 알고리즘을 활용").
   - 정답 보정 도구(`tools/rl/relabel_yellow.py`, `tools/rl/relabel_turn.py` 등)는 **학습 데이터에만** 쓰이고 주행 중에는 안 쓰이는지 확인한다 (L3).
   - 위험 장면 재시작(`DANGER_P`)이 있으면 L6 설명 방식으로 보고한다.
7. **평가 (E1)**
   - 최근 평가 결과(`eval.json`, `report.md`, `models/*/README.md`)에서 **충돌률만** 따로 적고 5% 미만인지 본다.
   - 평가 조건(지도, 교통량, `loop_flows`, `ROAD_DETAILS`, SUMO 버전, 횟수, 시드)을 같이 적는다. 팀 기준 SUMO는 1.27.1(`requirements.txt`).
8. **데이터 (D1~D3)**
   - 제출할 데이터의 수집 코드와 형식(`DATA_FORMAT.md`)을 보고, **모든 행에 state(절대 상태)가 있는지** 확인한다.
   - transition 수를 센다. state가 없는 데이터(예: DAgger 학습용 `obs/accel/lane_cls`만 있는 npz)는 10^7에서 뺀다.
   - 수업 기본 수집 항목이 모두 있는지 `DATA_FORMAT.md` 0절 표와 대조한다.

## 4. 이 저장소에서 이미 알려진 사항 (2026-11-23 기준, 점검 때 다시 확인)

- **R3 (제한속도 자르기):** 수업 원본 코드부터 `env/sumo_env.py` `step()`이 `setSpeed(np.clip(v + dv, 0, vmax))`로 50 km/h에서 잘랐고, AV 차종 `maxSpeed`도 50 km/h였다 → 위반.
  브랜치 `claude/optimistic-euler-8s91w5`(커밋 `b913a2f`)에서 고쳤다: 상한을 차량 성능 최고속도(`EGO["max_speed"]` 100 km/h)로 바꾸고, 차로 제한속도 초과는 `REWARD["overspeed_penalty"]`(스텝당 0.5 × 초과 비율)로 감점한다. **main에는 아직 없다.** 고친 환경으로 학습한 모델만 요건에 맞는다.
- **R4:** `lane_change_safety.enabled = False` (꺼 둠. 켜도 허용).
- **O1:** `lane_route_info = False` (차로 단위 경로 안내 꺼 둠).
- **O3:** `junction_foes.enabled = False`.
- **확인 필요:** 노면 화살표 관측(41~55), 앙상블 모델(`models/yeonsan_7routes_J8` 등 8개 평균)이 "신경망 하나"에 맞는지.
- 루프 B 모델(`models/yeonsan_loopB_RL`)은 단일 신경망이고 마지막 단계가 PPO다. 단 R3를 고치기 전 환경에서 학습했다.
